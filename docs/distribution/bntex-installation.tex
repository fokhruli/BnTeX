{\Large\bfseries BnTeX: Bengali in pdfLaTeX}\par
Version 0.2.1-alpha\quad|\quad BnTeX contributors\par\medskip
\textbf{Status.} Alpha release. Only the bundled Noto Serif Bengali Regular and
Bold fonts are supported. Tested with TeX Live 2023 (Linux), TeX Live 2026 on
Overleaf, and MiKTeX 25.4 (installed, and with the files beside the document).

\section{Installing}
\textbf{TeX Live.} Unzip \texttt{bntex.tds.zip} into \texttt{TEXMFHOME}
(\texttt{kpsewhich -var-value TEXMFHOME}) or another TEXMF tree.

\textbf{MiKTeX.} Unzip \texttt{bntex.tds.zip} into a folder of your own and
register it as a root, in MiKTeX Console (\emph{Settings, Directories}) or with
\texttt{initexmf -{}-register-root=}\emph{folder}. In a root that is already
registered, run \texttt{initexmf -{}-update-fndb} after unzipping.

\textbf{Overleaf or a single project.} Place the runtime files from
\texttt{tex/latex/bntex/} and \texttt{fonts/*/*/bntex/} in the document's own
folder. The release's \texttt{bntex-overleaf-starter.zip} is such a project:
upload it with Overleaf's \emph{New Project, Upload Project} and keep the
pdfLaTeX compiler. The same layout works locally with TeX Live or MiKTeX.

\section{The author interface}
Load one package:
\begin{Verbatim}[fontsize=\small]
\documentclass[12pt]{article}
\usepackage{bntex}
\begin{document}
% Type Bengali and English here as ordinary Unicode text.
\end{document}
\end{Verbatim}
The package enables Bengali detection and loads its default supported regular
and bold profiles automatically. No language wrapper, explicit profile loader,
Python command, font path or vocabulary preparation belongs in the document.
Run pdfLaTeX again after changing or adding words.

\textbf{Word cache.} Shaping runs in TeX macros, so a first compilation handles
roughly 100--150 distinct words per second. BnTeX writes every shaped word to
\texttt{\string\jobname.bnc} beside the \texttt{.aux} file and reuses it in
later compilations, shaping only new words; on Overleaf a 5,000-word document
recompiled in 2.5\,s instead of 38\,s. Output is identical with or without the
cache, and deleting the file is always safe. It is ignored unless written by the
same installation, and each line carries an MD5 so damaged lines are shaped
again. \texttt{[no-word-cache]} disables it; \texttt{\string\BnTeXCacheStats}
prints hits and misses.

To opt in to simulated italic appearance, load
\texttt{\string\usepackage[synthetic-italic]\{bntex\}}.
The accompanying \texttt{bntex-example.tex} contains real Bengali source.
Bengali in mathematics belongs in amsmath's \texttt{\string\text\{...\}};
this is not a Bengali math alphabet or a verbatim Unicode-font package.

\textbf{Searching and copying.} Every word carries its original text as
\texttt{/ActualText}, which viewers such as Poppler's return exactly. Viewers
that ignore it, including Overleaf's preview and Firefox's built-in viewer
(PDF.js), use each glyph's Unicode text: the letters are right, but vowel signs
drawn left of their consonant and reph come out in drawing order.

\section{Legacy migration}
The older \texttt{bntex} package name selected a prepared-word cache. It no
longer does so by default. Such documents must select
\texttt{\string\usepackage[cached]\{bntex\}}, or explicitly load
\texttt{bntex-cached}. The legacy preparer creates an explicitly labelled
project-local compatibility shim without rewriting the author's source.
An old generated shim in a document folder shadows an installed package;
remove or migrate that old project intentionally before using the new interface.

\section{What the maintainer builds}
The complete runtime includes precompiled shaping tables, matchers, bold
positioning data, six metric/encoding banks, and the exact Regular and Bold
outline fonts. These are built once for the release, never per author or word.
Font binaries are not included in the repository or source-review download.

Files occupy conventional TDS directories:
\begin{Verbatim}[fontsize=\small]
tex/latex/bntex/
fonts/tfm/public/bntex/
fonts/enc/dvips/bntex/
fonts/truetype/public/bntex/
doc/latex/bntex/
source/latex/bntex/
\end{Verbatim}
The maintainer build produces deterministic TDS and browsing-style candidate
ZIPs. The shipped source directory includes \texttt{REPRODUCING.md}: its
maintainer-only rebuild compiles the manual and font data, requiring identical
runtime and archive bytes with a matching toolchain. It needs no development
checkout. Neither build command submits files or authorizes publication.

\section{Integrity and relocation}
Font-format searches differ from ordinary TeX input searches. The loader checks
assets in standard TeX Live roots and reuses the same verified paths for maps
and metrics. Moving the whole TDS tree needs no rebuilt profile or baked-in
installation path. Missing or changed checked assets stop compilation.
MiKTeX's pdfTeX expands no \texttt{\$TEXMF} roots and cannot checksum files
under \texttt{fonts/}. On MiKTeX only, the loader then finds the installed font
files through MiKTeX's font search and compares every metric file, glyph by
glyph, with the MD5-checked shaping tables; the encoding and TrueType files
cannot be checked there.

Archive verification independently requires the complete file set, so deleting
both a file and its manifest entry still fails. Complete license text, matching
runtime/source modules, and both installed loaders are checked.
MD5 detects accidental drift, not coordinated malicious replacement; the
SHA-256 inventory is not a signature. Package-manager trust remains necessary.

\textbf{Read-policy compatibility.} Normal TeX Live input policy is tested.
Restrictive \texttt{openin\_any=p} behavior depends on the engine/Kpathsea version:
the local pdfTeX 1.40.26 refuses symbolic-root checksums. Tests probe the primitive
and require either checked rendering or a clear error. No policy is relaxed and
no check is skipped. The package invokes neither a shell nor \texttt{kpsewhich}.
When no TEXMF root resolves, assets are checked by bare name, which finds copies
beside the document under the same MD5 check. See the accompanying README for
the upstream 2026 input-policy change and its compatibility implications.
