\textbf{Status.} Engineering candidate for a complete TeX Live installation.
Not a CTAN submission, release approval, or Overleaf browser certification.

\section{The author interface}
Install BnTeX through the TeX distribution, then load one package:
\begin{Verbatim}[fontsize=\small]
\documentclass[12pt]{article}
\usepackage{bntex}
\begin{document}
% Type Bengali and English here as ordinary Unicode text.
\end{document}
\end{Verbatim}
The package enables Bengali detection and loads its default supported regular
and bold profiles automatically. No language wrapper, explicit profile loader,
Python command, font path or vocabulary preparation belongs in the document.
Run pdfLaTeX again after changing or adding words.

To opt in to simulated italic appearance, load
\texttt{\string\usepackage[synthetic-italic]\{bntex\}}.
The accompanying \texttt{bntex-example.tex} contains real Bengali source.
Bengali in mathematics belongs in amsmath's \texttt{\string\text\{...\}};
this is not a Bengali math alphabet or a verbatim Unicode-font package.

\section{Legacy migration}
The older \texttt{bntex} package name selected a prepared-word cache. It no
longer does so by default. Such documents must select
\texttt{\string\usepackage[cached]\{bntex\}}, or explicitly load
\texttt{bntex-cached}. The legacy preparer creates an explicitly labelled
project-local compatibility shim without rewriting the author's source.
An old generated shim in a document folder shadows an installed package;
remove or migrate that old project intentionally before using the new interface.

\section{What the maintainer builds}
The complete runtime includes precompiled Unicode/shaping tables, matcher
routines, bold positioning data, six metric/encoding banks, and the exact
Regular and Bold outline fonts. These are generated once for the release,
not separately for each author or each word. Font binaries are not in the
source repository or the downloadable source-review archive.

The local builder places files under the following TDS directories:
\begin{Verbatim}[fontsize=\small]
tex/latex/bntex/
fonts/tfm/public/bntex/
fonts/enc/dvips/bntex/
fonts/truetype/public/bntex/
doc/latex/bntex/
source/latex/bntex/
\end{Verbatim}
A deterministic local packaging operation produces a TDS ZIP and a complete
browsing-style CTAN candidate including that TDS ZIP. These are local maintainer
outputs. Building them does not submit or authorize publication.

\section{Integrity and relocation}
Font-format searches differ from ordinary TeX input searches. The installed
loader checks the canonical asset path in standard TeX Live roots and reuses
that same checked path for the actual font map and metric loading. It does not
check one file and then resolve a different file by basename. Moving the whole
TDS tree does not require rebuilding profiles or recording a new developer path.
Missing or changed checked assets stop compilation.

MD5 guards detect accidental drift, not an adversarial coordinated replacement.
A SHA-256 manifest inventories the complete local distribution. The manifest is
not a digital signature. Installation and package-manager trust remain necessary.

\textbf{Read-policy compatibility.} Normal TeX Live input policy is tested.
Under \texttt{openin\_any=p}, the local pdfTeX 1.40.26 refuses symbolic-root
checksums, while the TeX Live 2023 CI engine permits them. Tests independently
probe the primitive and require rendering plus corruption rejection when
readable, or a clear error otherwise. The package never relaxes the policy
or skips integrity checks. This is not an all-platform compatibility claim.
Custom search trees outside the documented standard roots and MiKTeX are not
yet validated. The code does not invoke a shell or \texttt{kpsewhich} at runtime.
